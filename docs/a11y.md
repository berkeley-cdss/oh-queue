# Web Accessibility

Berkeley websites must meet [WCAG 2.1 AA](https://www.w3.org/TR/WCAG21/) (see Berkeley's
[Digital Accessibility page](https://dap.berkeley.edu/)). The `A11y` workflow checks every page of the
app against it on each push and pull request, as [sections](https://github.com/berkeley-cdss/sections/blob/main/docs/a11y.md)
and [seating](https://github.com/berkeley-cdss/seating/blob/main/docs/a11y.md) do.

## What the tests do

`tests/a11y/conftest.py` seeds a course: assignments, a location, and tickets in each state (a student's
own, waiting; one a TA is helping; one resolved), and an active group. `tests/a11y/test_a11y_pages.py`
starts the app and opens every page in headless Chrome (`tests/browser.py`, shared with the end to end
tests), signed in through the dev login (the fake Canvas) as the kind of user who sees it: a student, a TA, or no
one. Course pages are the React app, so each audit waits until the page's data has loaded. On each page it
runs [axe-core](https://github.com/dequelabs/axe-core) twice:

- `test_meets_wcag_21_aa` checks the `wcag2a`, `wcag2aa`, `wcag21a` and `wcag21aa` rules, which Berkeley
  requires.
- `test_meets_wcag_22_aa` checks the `wcag22aa`, `best-practice` and `section508` rules. Every page meets
  these too, so they must pass as well. (Sections and seating only report them.)

An audit also fails if the page didn't load: if it redirected somewhere unexpected, showed an error page,
or the course page said it couldn't find what it shows.

`test_every_page_is_audited` fails when a new Flask route, or a new route in the React app
(`src/components/app.jsx` and `admin_layout.jsx`), isn't in `PAGES` (or, for a Flask route,
`SKIPPED_ROUTES`, with a reason).

## Adding a page

When you add a page, add it to `PAGES` in `tests/a11y/test_a11y_pages.py` in the same pull request, so it's
audited from the start. Each entry is a `Page` with:

- `name`: what the audit's reports and test IDs call it, such as `"admin tickets"`.
- `rule`: the Flask route that serves it. Every course page is the React app, served by
  `/offerings/<int:canvas_course_id>/` (the course's home page) or `COURSE_RULE` (every other course page).
- `path`: the URL to open. A page about one ticket, group or user uses the seeded course's IDs, such as
  `f"{COURSE}/tickets/{{assigned}}"`. `seed()` in `tests/a11y/conftest.py` returns them, so add what your
  page needs there.
- `user`: `STAFF`, `STUDENT`, or `None` for someone signed out. Add a page once for each kind of user who
  sees something different on it.
- `route`: for a course page, its route as written in `src/components/app.jsx` (such as `"/tickets/:id/*"`),
  or `"admin:"` and its route in `admin_layout.jsx` (such as `"admin:tickets/*"`).
- `lands_on`, if opening the page redirects, and `error=True` for one of the error pages.

A page that isn't a page someone visits (a redirect, or a file) goes in `SKIPPED_ROUTES` with the reason
instead. `test_every_page_is_audited` fails until every route is in one of them, and says which. Then run
`yarn build && pytest tests/a11y` and fix what the new page breaks.

## Running them

The course pages need the frontend build, as in the Docker image:

```bash
yarn build
pytest tests/a11y
```

Rebuild after changing the frontend. You need Chrome installed. When a page fails, the test prints each
broken rule with the elements that break it, and the end of the run lists the pages for each rule. The full
axe report for every page is saved in `axe/`, with a screenshot of each failing page in `axe/screenshots/`. In
CI, these are uploaded as the `axe` artifact of a failed run.

## Exceptions

`SKIPPED_RULES` in `tests/a11y/utils.py` turns an axe rule off for every page, and elements marked
`data-a11y-errors="true"` are left out of every rule. Both are a last resort: fix the page if you can, and
keep an exception as small as possible, with a comment saying why.

## What the tests can't check

axe finds roughly a third of WCAG problems. Check these by hand when you change a page:

- Everything works with the keyboard alone, in a sensible order, with a visible focus outline.
- A screen reader (VoiceOver: <kbd>Cmd</kbd>+<kbd>F5</kbd>) announces controls, messages and dialogs sensibly.
- The page still works zoomed to 400% (or at 320px wide) without scrolling sideways.
- The contrast of text axe marks as "incomplete".

The audit opens each page as it first loads. Menus, dialogs (such as the description box after requesting
help) and the states after an action aren't audited, so check them by hand when you change them.
